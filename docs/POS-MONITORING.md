# POS 自動檢測範圍

## 每日執行

CI 在每天台灣時間 08:17（UTC 00:17）排程；GitHub 排程可能延遲，沒有準點或持續監控保證。可從 CI 的 Run workflow 手動執行。新排程僅在工作流程合併到預設分支後生效。

- `verify`：一次性 PostgreSQL 容器、合成帳號商品、型別與回歸測試、正式模式建置、桌機／手機瀏覽器下單。核對確認前零交易、完成後一筆、庫存7→6、售價及分潤、紀錄篩選與CSV。
- `production_probe`：沿用已稽核的固定GET清單，只檢查 manifest 正式 origin 的公開頁面及未登入權限閘門，不讀寫店家帳務、不登入、不呼叫核銷或cron。獨立執行，不因隔離測試失敗而略過。
- 瀏覽器失敗證據及正式站公開檢查報告保留7天。失敗不自動重試、不改寫正式資料或自動發布。

## 登入後隔離驗收

沿用同一份 Playwright 桌機及手機設定，使用一次性 CI PostgreSQL 的隨機合成 HQ 與店家帳號，透過真實登入表單驗證，不共用兩套 session。

- HQ：營運首頁、訂單七項統計、待審核、商品、庫存與補貨申請。統計未知不得當成通過。
- POS：庫存、換罐、美容券空輸入停用、對帳流水切換，以及叫貨規格選擇、確認與返回；確認前後核對銷售及補貨申請數不變。
- 保留原有下單、扣庫存、分潤與 CSV 驗收；寫入僅發生在一次性 CI 資料庫。

上述仍不是正式站登入後巡檢。正式資料、跨店權限、真實金流、物流與 LINE 對話未因此取得完整驗收。成功需以對應 SHA 的實際 CI 結果為準。

持續檢查報告：[FURMOSA HQ 與 POS 系統檢查及自動維護報告](https://chatgpt.com/space/page_b8cc596e44208191b63025d465d3c511)。更新同一份報告，保留觀測日期與未驗證項目；此私人連結不授予讀取權限。

## 正式站與隔離測試的判讀

隔離下單通過不代表正式站登入後的功能正常；公開頁面200也不代表店家按鈕正常。兩份結果必須分開回報。當日排程未執行、尚未完成或無權讀取時，不能沿用舊綠燈。

正式站登入巡檢已有待驗收的程式及手動工作流程，尚未啟用每日執行；核銷、交付與完整結算也尚未納入正式瀏覽器寫入驗收。既有每日隔離測試不使用正式帳號或正式測試單。

## 正式登入巡檢候選版：尚未啟用

`Authenticated production monitor (read-only)` 只允許 main 手動執行，沿用 production Environment 的 reviewer 閘門。這個 PR 不配置秘密、不新增帳號或權限、不部署、不改既有每日 CI。完成真實站驗收與權限決策前，不加入 schedule，也不能回報已每日登入檢測。

- 沿用 production Environment 既有 `PRODUCTION_SMOKE_HQ_EMAIL`、`PRODUCTION_SMOKE_HQ_PASSWORD`，映射為 runner 的 MONITOR_HQ_*；不讀取、不複製秘密值。POS 使用 `MONITOR_POS_USER`、`MONITOR_POS_PASSWORD`。新增保存指定 POS 憑證前必須取得明確授權；不能把先前瀏覽器登入授權視為憑證保存授權。四個 runner 登入值缺任一項直接失敗，不能略過後回報成功。不使用 DB 連線、簽章密鑰或自製 Cookie。
- 真實登入會更新既有 lastLoginAt／建立工作階段；「唯讀」指不修改業務資料，不代表登入完全沒有寫入。HQ 與 POS 使用分離、一次性瀏覽器 context；不保存 session。選用既有具適當權限且有可銷售商品的店家帳號；無商品時搜尋功能驗收不通過，不憑空建立正式商品。
- HQ 桌機：營運首頁、訂單數字統計、待審核、商品、庫存、補貨申請。POS 手機：商品搜尋與清除、庫存、換罐、叫貨、紀錄、對帳及流水切換。不選取真實案件、不送單、不審核、不交付、不結算、不核銷、不標已讀。
- 僅放行固定同源頁面與靜態程式；每套 context 只放行一次登入 POST。POS 兩個已稽核、無參數的通知讀取 Server Action，從同源 bundle 的具名引用解析 ID；其他 POST／PUT／PATCH／DELETE 全部封鎖並使結果失敗。Next bundle 格式變動也採失敗關閉，需人工核對更新，不能擴成任意 POST。
- 明確排除美容券頁面：其 GET 讀取可能執行逾期更新。圖片、外站與預取不屬於覆蓋範圍。未預期的非資產請求被封鎖時回報 REQUEST_BLOCKED，不將其判成正式站本身故障。
- 只保留固定檢查代碼、通過／失敗、時間與耗時；不保留 DOM、回應內容、錯誤原文、帳號、Cookie、截圖、trace、HAR、下載或 storageState。正式結果 artifact 保留7天；無自動重試、修復或發布。
- CI 使用完全相同的 runner 對一次性 localhost 資料庫驗收，並核對沒有新增 sale 或 RestockRequest。localhost 特例只接受 CI=true 加兩條精確 CI DB URL；CLI 正式入口不能覆寫 origin。隔離通過仍不等於正式帳號與資料已驗收。

## 修復與通知

ChatGPT 的獨立排程可讀取最新檢查、比對失敗步驟、嘗試重現，並為可定位的程式錯誤建立修復分支及草稿PR。它是條件式修復協助，不保證每次能完成修復。不可自動合併、部署、改秘密／權限、migration、操作正式帳務或降低測試標準。讀不到新結果或需要使用者處理時須明確通知。

部署持續依 AGENTS.md 的 Deploy Production 流程。正式站公開巡檢不需要 Production secrets。

## 首次正式驗收失敗與檢測器修正

PR604已透過發布172上線，合併SHA369875ad0b770b1d2513e4622fd70aaafa655ecb。首次正式巡檢run42204384186在context.close時仍有route.fetch，未捕捉的TargetClosedError造成程序中斷，報告未產生。不能據此回報任何正式功能通過。

修正版保持請求防護直到context完全關閉，捕捉每個route callback的例外，關閉後等待已追蹤請求結束；只記錄固定失敗代碼，不輸出原始錯誤或Cookie。工作流程先建立失敗狀態的備援報告，避免程序中止時沒有artifact。回歸測試模擬context關閉才失敗的延遲請求，核對runner仍回傳失敗報告且不洩漏錯誤內容。這項修正不改業務功能、權限、憑證或排程；未經新版受控發布，不重跑正式驗收。

## 第二次正式巡檢與資產排除判讀

PR605已透過發布173上線，合併e44544ad47c3ffd448eedaf8286196f584ec973b。正式巡檢run42206957859成功保留報告：HQ登入、訂單統計與待審核頁通過；HQ商品頁、POS登入後收銀標題階段因REQUEST_BLOCKED未通過。報告無被攔請求分類，不能將它直接判成正式功能故障，也不能證明所有封鎖都來自圖片。

源碼回歸發現：外站圖片／字型在排除前就因跨來源被算成失敗，與既定「不驗圖片」範圍不符。修正只讓這些GET資產被省略時不產生功能失敗；仍然abort，不對外傳送。跨來源資料、程式、所有寫入及未知同源操作仍失敗關閉。新增最多每角色10筆固定分類診斷，只記method、resourceType、同源／他源、固定允許頁面或unlisted及固定reason；不記主機、完整URL、query、動態ID、header、body或例外原文。

本對話另以既有NOVA咖啡工作階段在正式POS實測搜尋、加入本單、結帳確認畫面、返回及移除，已還原空單，未按確認完成；不等於niuniu或完整送單驗收。此修正不更動業務功能、權限、憑證或排程；未重跑正式巡檢。
