# 店家身分確認：正式小範圍上線計畫

第三層還沒執行。這份只說明以後怎麼開、怎麼關。

## 原則

- 預設關閉。沒有打開開關，正式站不能寫入確認、撤銷、新增、開通、修改或刪除。
- Preview 繼續只讀，不拿正式庫做寫入驗收。
- 不改店家 slug、MER、會員、折價券、訂單、點數或店員。

## 1. 功能預設關閉

正式環境變數保持：

- `PARTNER_STORE_IDENTITY_WRITES` 不要設成 `enabled`

沒有這支開關，伺服器會回「正式環境尚未開放寫入店家身分」。

## 2. 只開給指定 HQ 帳號

打開開關後，還要再加允許名單，例如：

- `PARTNER_STORE_IDENTITY_WRITERS=admin@example.com`

不在名單裡的總部帳號，畫面不出現寫入按鈕，伺服器也拒絕。

## 3. 先用 MER-DEMO 做一筆測試標記

1. 只對 `MER-DEMO` 寫一筆「示範」標記。
2. 確認人是實際 HQ 帳號，時間是實際操作時間。
3. 正式合作清單與正式統計都看不到 MER-DEMO。
4. 財務對帳數字不能被這筆標記藏起來。

## 4. 驗證後才套用五組真店

測試標記沒問題後，才一筆一筆確認：

1. 豬窩板橋 `zhuwo_banqiao` ↔ `MER-0019`
2. 豬窩土城 `zhuwo_tucheng` ↔ `MER-0020`
3. 豬窩中和 `zhuwo_zhonghe` ↔ `MER-0016`
4. 曼利莎 `manlisa` ↔ `MER-0017`
5. 淡水妞妞 `niuniu` ↔ `MER-0010`

一次只確認一家。確認後立刻核對清單是一列、豬窩三家分開、pet99 仍待確認。

## 5. 立即關閉與撤銷

關閉：

1. 把 `PARTNER_STORE_IDENTITY_WRITES` 從正式環境刪除或改成不是 `enabled`
2. 重新部署 Production
3. 寫入按鈕消失，伺服器拒絕新的寫入

撤銷：

1. 在允許名單帳號下，對該筆確認填撤銷原因
2. 原紀錄保留，店家回到待確認
3. 不刪 MER、slug 或交易

若只要拿掉 MER-DEMO 測試標記，撤銷那一筆即可，不必關整個功能。
