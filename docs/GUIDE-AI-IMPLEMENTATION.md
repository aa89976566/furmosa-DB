# 匠寵 AI 導購：第一個工作包

這個工作包提供對話理解、商品適用判斷、許願表單及 HQ 審核。尚未正式部署；原導購介面未修改。

## 已實作

- Responses API 結構化理解，保留物種／需求／年齡／避免食材／其他要求。
- 同一動物不重問物種；明確切換動物時清除前一隻的條件。
- 食材、低脂、年齡、物種、缺貨皆由程式硬性篩選，模型不能自行選商品。
- 不符合或資料不足時回傳 wish；健康／治療問題回傳 handoff。
- 上游錯誤不包含金鑰、原始對話或服務回應；API 請求 store=false。
- `/wish` 表單收物種、需求、LINE ID；只有持久化完成才顯示成功。
- 使用既有 Task 模型，todo 顯示待審核；無 schema 變更或 migration。
- `/wishes` 僅 HQ admin/staff 可檢視聯繫資料與更改狀態。原任務看板只顯示許願入口，避免把 LINE 資料 JSON 印在通用看板。
- 交易內鎖定、重送冪等、每來源 24 小時 5 筆／全站 100 筆限流；不保存原始 IP。

## 尚未接通，不能視為上線完成

1. OPENAI_API_KEY 安全儲存被確認工具拒絕；伺服器查無既有金鑰，沒有建立或寫入新金鑰。
2. 需要把 Shopify 經核實的適用資料轉為 Product 合約；不能用名稱或一般標籤推論安全。
3. 公開聊天入口須有驗證、共用限流與請求大小限制；目前不新增未保護的公開 route。
4. 許願程式已完成單元測試；尚待隔離資料庫的真實持久化、併發及手機／桌機表單驗收。未啟用公開入口。
5. UI 必須沿用使用者確認的原始設計與抽象藍狗資產；本工作包沒有變更 CSS。

## 許願池啟用條件

先在隔離 Preview 驗收，不能將 Preview 指向正式資料庫。

- `FURMOSA_WISHES_ENABLED=true` 才開放精確 `/wish` 路徑；其他 HQ 與 POS 路徑保持既有驗證。
- `WISH_FORM_SECRET`：獨立隨機秘密，至少32字元；不得重用 AI、LINE、付款或驗證 secret。
- `WISH_TRUSTED_IP_HEADER`：必須先核實部署代理會覆寫且不能由訪客偽造的單一 IP header。缺少、無效或含多值時拒絕收件；不得隨意信任 x-forwarded-for。
- 許願池本身不使用 AI；LINE ID 絕不送入模型。
- 預設關閉，不在這次提交設定正式 secrets、啟用功能或寫入正式資料。

## 後續驗收

- 「兔兔想找磨牙玩具」不再問物種；無適用品顯示許願池。
- 「狗狗不吃雞，想找訓練零食」不重問雞肉，不推薦成分未知品。
- 「換幫貓咪找」不沿用狗狗的年齡與限制。
- 全流程只能推薦實際上架、可購買且通過標示核對的商品。
- 許願只有持久化成功才顯示成功；LINE ID 不傳給模型。
- 必須通過隔離 Preview 的實際模型與 HQ 收件驗收，才依既有 release 流程上線。
