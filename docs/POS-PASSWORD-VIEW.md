# HQ 管理員查看 POS 密碼

## 使用方式

HQ 店家總覽的 POS 帳號區，只有目前資料庫角色為 admin 的使用者可見「顯示密碼」及「保存目前密碼」。舊帳號需輸入目前密碼，驗證成功後才加密保存；這不會重設登入密碼。HQ 新建及重設帳號則同時保存加密值。

密碼按需載入，初始頁面與帳號列表不傳送密碼或密文。顯示後 30 秒或切換分頁自動隱藏。每次保存、查看、新建與重設都記錄操作管理員、POS 帳號、動作與時間，不含密碼、雜湊或密文。非管理員、無效登入或跨店家參數會在伺服器被拒絕。

AES-256-GCM 使用隨機 nonce，驗證資料綁定 POS 帳號 ID 及目前登入雜湊。其他途徑重設密碼後，舊密文無法解密；需重新驗證及保存目前密碼。保存使用 compare-and-set，避免與密碼重設競爭。

## 上線順序

1. 在 Railway 與 Vercel 對應環境設定相同的 `POS_PASSWORD_ENCRYPTION_KEY`（安全亂數產生的 32 bytes，base64 編碼）。金鑰不可提交版本控制、輸出日誌或設定成 NEXT_PUBLIC。Preview 若使用另一個資料庫，必須使用獨立金鑰。
2. 核對 `merchant_users` 欄位後，只執行 `20260915130000_pos_password_vault`；新增 nullable encrypted_password 欄位及獨立操作紀錄表，不重設任何密碼，不影響現有庫存或訂單。
3. 執行 Prisma migration resolve 登記該 migration；不要一次執行其他待辦 migrations。
4. 合併及部署後，以管理員驗證保存及顯示；非管理員直接呼叫 action 必須被拒絕。保存泡泡堂密碼時只透過驗證表單，不把真實密碼放入 SQL、程式碼或文件。
5. 缺少金鑰時，保存、新建及重設會拒絕執行，原有 HQ/POS 登入仍不受影響。

## 回復

先回復到部署前程式，再移除密碼保管金鑰。原 password_hash 保持有效，既有登入不依賴本功能。加密欄位及操作紀錄可留存；清除或刪除需另行決定。金鑰輪替需先以舊金鑰解密、以新金鑰重新加密；不可直接覆蓋唯一金鑰。

## 驗證

密文竄改、錯誤金鑰、跨帳號、密碼重設後舊密文、缺金鑰、無登入、已降權管理員、跨店家、錯誤目前密碼、並行重設及稽核失敗均有測試。真實密碼不納入測試資料。
