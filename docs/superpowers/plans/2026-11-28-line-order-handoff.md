# LINE 訂單付款後出貨交接計畫

## 目標

LINE 對話購物建立的 HQ 訂單，在 HQ 人工核帳改為「已付款」時，原子地建立一張含完整收件資料與商品快照的待出貨單。未付款、資料不完整或重複操作時不得建立錯誤或重複出貨單。

## 範圍

- 僅處理 `source=line`、`externalStore=line-chat` 的訂單。
- 沿用既有 Order、Shipment 與 ShipmentItem，不新增 schema 或 migration。
- 收件姓名與電話從 LINE 訂單既有固定格式備註讀取；地址、超商與物流使用 Order 的結構化欄位。
- 既有有效出貨單存在時不重複建立。
- 其他來源訂單維持既有付款狀態更新行為。

## 實作步驟

1. 先新增純函式測試，涵蓋 LINE 收件資料解析、付款狀態判斷、缺資料阻擋與重複出貨保護。
2. 建立 LINE 訂單付款交接規劃器，輸出安全的 Shipment 建立資料。
3. 將 HQ 付款狀態更新接上規劃器；在同一資料庫交易內更新付款與建立出貨單。
4. 補上並行安全、商品快照及宅配／7-ELEVEN 的回歸測試。
5. 執行針對性測試、型別檢查、完整測試與差異檢查。
6. 僅建立 Draft PR；不合併、不部署、不修改正式資料。
