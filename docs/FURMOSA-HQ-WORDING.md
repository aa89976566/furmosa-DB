# Furmosa HQ 統一用詞

> 狀態：v0.2 視覺規則待總部驗收
>
> 原則：先說人現在能不能做，再說原因與下一步。

## 1. 店家與合作

| 統一用詞 | 意思 | 不使用 |
|---|---|---|
| 店家編號 | 一間實際門市的唯一編號，例如 `MER-0018` | 寄賣編號 |
| 合作店家 | 與匠寵開啟至少一項合作功能的門市 | 核銷店、寄賣身分 |
| 合作功能 | 換罐、寄賣、美容折抵，可多選 | 店家身分 |
| 舊核銷連結 | 舊系統沿用的門市連結 | 第二個店家、店家編號 |
| 開通合作 | 在既有門市增加合作功能 | 新增一間店 |
| 建立新門市 | 確認不存在後，建立新的實際門市 | 再開一筆看看 |

## 2. 合作店家狀態

| 顯示文字 | 人話說明 | 下一步 |
|---|---|---|
| 可核銷 | 這家店今天可以完成核銷 | 開始核銷 |
| 尚未連上換罐資料 | 店家資料還沒完成對應 | 完成設定 |
| 尚未開放核銷 | 店家存在，但尚未開啟核銷功能 | 開放核銷 |
| 待總部確認 | 找到相似資料，確認前不新增功能 | 查看並確認 |
| 已停用 | 保留歷史，但不能建立新交易 | 查看停用原因 |
| 測試／示範 | 只供內部驗收，不列入正式營運 | 查看測試紀錄 |

不得在店員畫面顯示「未標記後台」「slug 對不上」「孤立資料」等內部語言。

## 3. 任務頁的固定文字順序

每一步只使用以下五層，不再插入第二組標題或長篇教學：

1. 頁面名稱，例如「新增訂單」或「新增／開通合作店」。
2. 進度名稱，例如「訂購對象、基本資料、商品、確認」。
3. 步數提示：「第 X 步，共 Y 步」。
4. 當前問題，例如「選擇訂購對象」或「先找找這家店」。
5. 一句協助文字，回答現在怎麼做。

協助文字使用「先做什麼，再做什麼」的句型。例如：「先搜尋既有資料，找不到時再新增。」

## 4. 新增店家流程

| 情境 | 使用文字 |
|---|---|
| 入口 | 新增／開通合作店 |
| 第一步標題 | 先找找這家店 |
| 第一步說明 | 先搜尋既有門市，確認找不到時再建立。 |
| 搜尋提示 | 搜尋店名、電話或店家編號 |
| 找到既有店 | 使用這家店 |
| 找到相似資料 | 需要總部確認後才能繼續 |
| 完全找不到 | 確認找不到，建立新門市 |
| 功能選擇 | 這家店要合作哪些服務？ |
| 下一步 | 繼續選合作功能 |
| 完成 | 這家店已準備好 |

合作店家流程不可使用「新增客戶或店家」，因為客戶與門市不是同一種資料。只有訂單流程需要同時選擇不同訂購對象時，才可使用這類集合文字。

## 5. 搜尋結果的文字順序

- 第一行：可辨認的姓名或店名。
- 第二行：角色／合作功能，再接必要辨識資料。
- 相似資料：直接顯示「待總部確認」，並說明「確認前不能建立新門市」。
- 沒有結果：先寫「找不到符合的門市」，再提供「建立新門市」。
- 內部技術值只在詳細資料顯示，不塞在主結果列。

## 6. 動作文字

- 按鈕以動作開頭：完成設定、開放核銷、查看原因、繼續、確認建立。
- 下一步若會產生明確結果，直接寫結果，例如「繼續選合作功能」「建立門市並開通換罐」。
- 不使用模糊文字：處理、送出、確定、OK、更多操作。
- 取消或撤銷要說清楚對象，例如「撤銷妞妞的門市確認」。
- 成功訊息要說結果，例如「換罐合作已開通」，不只寫「操作成功」。
- 停用按鈕附近必須顯示原因，例如「請先選擇一間門市」。

## 7. 價格與交易

- 第一罐：NT$129。
- 空罐換新口味：NT$99，一罐換一罐。
- 每個有效 8 碼序號累積 1 點。
- 10 點可換美容折價，多數 NT$200；豬窩 NT$250。
- 店員畫面顯示系統決定的價格，不顯示可自行輸入的換罐價格。
- 取消、改價與例外必須顯示影響及留下紀錄。

## 8. 語氣

- 簡短、可靠、像熟悉店務的夥伴。
- 不責怪店員或毛爸媽。
- 不用工程名詞解釋營運問題。
- 每個錯誤都回答：「為什麼」與「現在怎麼做」。
