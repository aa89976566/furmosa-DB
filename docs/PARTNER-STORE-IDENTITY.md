# 匠寵如何認定同一家店

**店家身分規則已於 2026-08-29 正式鎖定。**  
這份文件是下一圈判定程式的正式依據。

本次鎖定範圍只包含：

- 一個 `MER-xxxx` 對應一個實際營運門市
- 合作功能可以多選，不代表寄賣身分
- slug 只是舊資料連結
- 分店、搬家及改名的判定方式
- 待確認期間的操作限制
- 人工確認的留存紀錄
- 一對一、待確認、衝突、孤立四種分類

這**不等于**同意合併舊資料，也不代表新增店家入口已經定案。  
PR #160 仍不要合併。

相關規則第 3 條：

> 所有入口共用同一個店家編號與同一筆交易紀錄。

---

## 一家店是什麼

> **一個 `MER-xxxx` 代表一個實際營運門市。分店各自編號；搬家或改名經總部確認後沿用；停用編號永久保留，不得重複發放。**

同公司多間門市可以共用結算資訊，但庫存、店員及交易仍按門市區分。

---

## 1. `MER-xxxx` 是店家編號，不是寄賣身分

`MER-xxxx` 只代表這一個門市。  
寄賣、換罐、美容折抵是這家店上可以多選的合作功能，不是三種身分。

必須成立：

> 只參加換罐、不做寄賣的店，也能取得 `MER-xxxx`，而且不會因此被開通寄賣。

現況備註（還沒改程式）：

- 現在發號是寫在店家主檔上，例如 `MER-0018`。
- 類型已可複選；理論上可以只勾「換罐」、不勾「寄賣」。
- 但「新增店家」畫面預設勾寄賣，標題也寫成寄賣通路。之後從換罐計畫開店時，**不可沿用這個預設**。
- 沒勾寄賣，就不得出現寄賣庫存、寄賣結算或寄賣出貨。

舊寄賣店繼續用現在的 `MER-xxxx`，不必重發。

---

## 2. slug 只是舊資料的連結，不是第二個店家身分

核銷 `Store.slug` 只用來對回舊的 LINE 開戶、折價券與結帳報表。  
它不是另一套店家編號。

### 什麼時候算「一對一」

必須四項同時成立：

1. slug 可以明確轉回唯一 `MER-xxxx`  
   例如 `mer_0018` → `MER-0018`
2. 這個編號確實存在
3. 沒有另一筆核銷店也對到同一個編號
4. 沒有另一個編號也對到同一個 slug

這是安全對應。少一項就不是一對一。

- 有候選、需要總部判斷 → **待確認**
- 重複編號、重複 slug、一對多或多對一 → **衝突**
- 指向不存在的店家、會員或 slug → **孤立**

舊的自訂 slug（例如 `niuniu`、`zhuwo_zhonghe`）轉不回 `MER-xxxx`，列為待確認。

同一編號或同一 slug 出現兩次，屬於**衝突**，不是一對一，也不是可自動確認。

| 資料 | 現在認哪個 | 之後怎麼看 |
|---|---|---|
| 門市本人 | `MER-xxxx` | 一個門市一個編號 |
| POS 店員帳號 | 掛在該門市主檔 | 換店員、改密碼不准另開一間店 |
| 換罐訂單、庫存 | 掛在該門市 | 跟 `MER-xxxx` 走 |
| LINE 核銷、結帳報表 | 先認舊 slug | 只是舊連結 |

---

## 3. 分店或地址不同：不自動合併

系統**不可以**自動宣判「確定是不同店」。

同名但地址不同，也可能是：

- 搬家
- 舊地址沒更新
- 地址格式不同
- 公司登記地與營業地不同

豬窩中和店、板橋店這類分店名稱，同樣**不自動合併**。  
系統只能說：「目前不合併，請總部確認是分店、搬家，還是同一家。」

分店確認後各自取得（或沿用）自己的 `MER-xxxx`。  
搬家或改名經總部確認後，沿用原來的編號。

---

## 待確認期間

可以暫時維持兩筆，並標記為**待確認**。

限制改為：

> **待確認期間不得新增功能、改變連結或合併資料；原本已開通的服務維持，並列入總部優先確認。**

這樣不會把正在營業的門市核銷或結帳停掉。  
但也不能再替其中一筆加開換罐、核銷、結帳或美容折抵，也不能把兩筆偷偷接在一起。

只有總部可以確認。店員不能自己合併。

人工確認時只問：

1. 是不是同一個實際營運門市？
2. 還是分店、搬家、改名，或舊資料重複？

---

## 人工確認必須留紀錄

不能只把狀態改成「已確認」。

> **每次人工判定須記錄確認人、時間、判定依據、保留編號及另一筆資料的處理方式。**

另一筆資料的處理方式例如：併入保留編號、標成另一間分店、或停用並永久保留該編號。

---

## 只讀檢查的分類

檢查只讀取，不新增、不合併、不刪除、不修正，也不觸發 LINE、付款或同步。  
報告只有數量、問題類型與匿名編號，沒有會員姓名、電話、LINE。

七項統計都用同一組分類：

| 分類 | 定義 |
|---|---|
| 一對一 | 唯一編號與 slug 安全對應 |
| 待確認 | 有候選，但需要總部判斷 |
| 衝突 | 重複編號、重複 slug、一對多或多對一 |
| 孤立 | 指向不存在的店家、會員或 slug |

| 項目 | 一對一 | 待確認 | 衝突 | 孤立 |
|---|---|---|---|---|
| 1. 重複店家 | 無。能安全對上的不算重複 | 店名相同或很像，但還不能判定是同一門市或分店 | 同一編號或同一 slug 出現兩次 | 完全沒有編號或 slug 可對 |
| 2. 只有核銷、沒有店家主檔 | 無。缺主檔就不能算安全對應 | 自訂 slug 或店名有候選主檔 | slug 轉出的編號同時被另一筆占用 | slug 指向不存在的 `MER-xxxx`，也沒有候選 |
| 3. 核銷與店家主檔無法互相對應 | 只統計已安全對上的對數，供對照 | 有名稱或 slug 線索，需總部判斷 | 一對多或多對一 | 兩邊都指向不存在的對象，或完全沒有可對線索 |
| 4. 重複會員或 LINE 無法對應 | 一個 LINE、一個會員、對得上一間門市 | 同一支電話出現在兩個會員 | 同一個 LINE 掛在兩個會員編號 | 會員編號或 LINE 指向不存在的會員 |
| 5. 同名但不同地址或分店 | 無。系統不宣判不同店 | 店名相同、像分店，或地址不同，需總部確認 | 兩筆都主張同一個 `MER-xxxx` 或同一個 slug | 沒有地址、分店線索，也沒有有效編號 |
| 6. 一筆可能對到兩家店 | 無 | 名稱有兩個候選，但還構不成編號衝突 | 一筆核銷對到兩筆主檔，或一筆主檔對到兩筆核銷 | 連候選都組不出來，且指向不存在的編號或 slug |
| 7. 有店員帳號、交易或換罐紀錄，但找不到有效店家 | 帳號或交易已安全掛在一對一門市（供對照） | 店家主檔還在，核銷連結待確認；已開通服務維持 | 同一帳號或交易掛到兩間門市 | 帳號、交易、折價券、開戶或**有換罐紀錄的會員**指向不存在的店家或 slug |

補充：

- 「有換罐紀錄但店找不到」算第 7 項的**孤立**，不算第 4 項。
- 第 4 項只看會員與 LINE 是否重複或指向不存在的會員。
- 待確認期間若仍新增功能、改連結或合併，列為違規風險（只讀檢查只標出，不阻擋）。

---

## 鎖定後的工作順序

1. 判定程式（這一圈）
2. 只讀統計
3. 人工處理衝突
4. 先找店，找到才開合作

這一圈不做：修資料、合併店家、新增店家入口、改資料庫結構、部署，也不合併 PR #160。
