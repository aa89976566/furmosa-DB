# 匠寵如何認定同一家店

這份文件只談規則與風險。  
**規則尚未正式鎖定。這份 PR 不要合併。**

相關規則第 3 條：

> 所有入口共用同一個店家編號與同一筆交易紀錄。

---

## 1. `MER-xxxx` 是店家編號，不是寄賣身分

`MER-xxxx` 只代表「這一家實體店」。  
寄賣、換罐、美容折抵是這家店上可以多選的合作功能，不是三種身分。

必須成立：

> 只參加換罐、不做寄賣的店，也能取得 `MER-xxxx`，而且不會因此被開通寄賣。

現況備註（還沒改程式）：

- 現在發號是寫在店家主檔上，例如 `MER-0018`。
- 類型已可複選；理論上可以只勾「換罐」、不勾「寄賣」。
- 但「新增店家」畫面預設勾寄賣，標題也寫成寄賣通路。之後從換罐計畫開店時，**不可沿用這個預設**。
- 沒勾寄賣，就不得出現寄賣庫存、寄賣結算或寄賣出貨。

舊寄賣店繼續用現在的 `MER-xxxx`，不必重發。

---

## 2. slug 只是舊資料的連結，不是第二個店家身分

核銷 `Store.slug` 只用來對回舊的 LINE 開戶、折價券與結帳報表。  
它不是另一套店家編號。

### 什麼時候可以自動視為同一家

必須四項同時成立：

1. slug 可以明確轉回唯一 `MER-xxxx`  
   例如 `mer_0018` → `MER-0018`
2. 這個編號確實存在
3. 沒有另一筆核銷店也對到同一個編號
4. 沒有另一個編號也對到同一個 slug

這是一對一、沒有衝突。少一項就改為**待確認**，不得自動合併。

舊的自訂 slug（例如 `niuniu`、`zhuwo_zhonghe`）轉不回 `MER-xxxx`，一律待確認。

| 資料 | 現在認哪個 | 之後怎麼看 |
|---|---|---|
| 店家本人 | `MER-xxxx` | 唯一編號 |
| POS 店員帳號 | 掛在店家主檔 | 換店員、改密碼不准另開一間店 |
| 換罐訂單 | 掛在店家主檔 | 跟 `MER-xxxx` 走 |
| LINE 核銷、結帳報表 | 先認舊 slug | 只是舊連結；對不上就待確認 |

---

## 3. 分店或地址不同：不自動合併

系統**不可以**自動宣判「確定是不同店」。

同名但地址不同，也可能是：

- 搬家
- 舊地址沒更新
- 地址格式不同
- 公司登記地與營業地不同

豬窩中和店、板橋店這類分店名稱，同樣**不自動合併**。  
系統只能說：「目前不合併，請總部確認是分店、搬家，還是同一家。」

---

## 對不上時

可以暫時維持兩筆，但必須同時做到：

1. 標記為**待確認**
2. **確認前，兩筆都不得再開新的合作功能**（換罐、核銷、結帳、美容折抵）

否則總部仍可能分別替兩筆開通，重複會繼續長大。

只有總部可以確認。店員不能自己合併。

人工確認時只問：

1. 是不是同一間實體店？
2. 還是分店、搬家、改名，或舊資料重複？

---

## 只讀檢查的七項定義

檢查只讀取，不新增、不合併、不刪除、不修正，也不觸發 LINE、付款或同步。  
報告只有數量、問題類型與匿名編號，沒有會員姓名、電話、LINE。

每項都分成：可自動確認／需要人工確認／完全無法對應。

| 項目 | 可自動確認 | 需要人工確認（待確認） | 完全無法對應 |
|---|---|---|---|
| 1. 重複店家 | 同一編號或同一 slug 出現兩次（資料庫若有唯一限制，這項應接近 0） | 店名相同或很像，但不是一對一無衝突 | 看不出是同一家還是兩家，也沒有編號可對 |
| 2. 只有核銷、沒有寄賣／店家主檔 | 無。缺主檔就不能自動當成已開通 | slug 轉不回編號，或轉回的編號不存在，但店名有候選 | 沒有編號、也沒有相似店名 |
| 3. 核銷與店家主檔無法互相對應 | 僅計入上面「一對一無衝突」之外的剩餘筆數，本身不自動合併 | 有名稱或 slug 線索，但有衝突、一對多或多對一 | 兩邊都找不到可對的線索 |
| 4. 重複會員或 LINE 無法對應 | 同一個 LINE 掛在兩個會員編號（可標出衝突，不自動合併會員） | 同一支電話出現在兩個會員 | 有換罐紀錄但店編號找不到，或完全沒有店 |
| 5. 同名但不同地址或分店 | 無。系統不宣判不同店 | 店名相同／像分店，地址不同或分店名稱不同 | 沒有地址也沒有分店線索，只剩店名相似 |
| 6. 一筆可能對到兩家店 | 無 | 一筆核銷對到兩筆主檔，或一筆主檔對到兩筆核銷 | 連候選都組不出來 |
| 7. 有店員帳號或交易，但找不到有效店家 | 帳號或交易指向一個已不存在的店家編號 | 店家主檔還在，但核銷連結待確認；確認前不可再開功能 | 折價券、會員開戶寫著不存在的 slug |

衝突類型（報告要分開數）：

- slug 轉得回編號，但編號不存在
- 兩個 slug 對到同一個 `MER-xxxx`
- 兩個 `MER-xxxx` 對到同一個 slug
- 自訂 slug 轉不回編號
- 同名、地址不同
- 像分店名稱
- 一對多／多對一
- 待確認期間若再開功能，視為違規風險（這次只讀，只標出，不阻擋）
