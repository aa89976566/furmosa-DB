# 匠寵如何認定同一家店

這份文件只鎖定「店家身分」。  
**還沒有新增／開通店家入口。** 在對應規則與只讀檢查完成前，不建立第三種同步。

相關規則第 3 條改為：

> 所有入口共用同一個店家編號與同一筆交易紀錄。

---

## 唯一店家編號

| 用途 | 現在用哪個欄位 | 之後怎麼認定 |
|---|---|---|
| 唯一店家編號 | 寄賣 `Merchant.merchantId`，例如 `MER-0018` | 一家實體店只准有一個這個編號 |
| 核銷相容鍵 | 核銷 `Store.slug`，例如 `mer_0018` 或舊的 `niuniu` | 給 LINE 開戶、折價券、結帳報表用 |
| POS 店員帳號 | 掛在寄賣 `Merchant` | 換店員、改密碼都不准另開一間店 |
| 換罐訂單／庫存 | 掛在寄賣 `Merchant` | 跟店家編號走 |
| LINE 核銷與結帳報表 | 認 `Store.slug` | 沒對上編號時，報表會當成沒選店 |

舊資料怎麼對：

1. **舊寄賣店** → 編號就是現在的 `MER-xxxx`。不必重發。
2. **舊核銷店** → 先保留現在的 slug。若 slug 正好是 `mer_0018` 這種由編號推導出來的值，系統可自動當成同一家。
3. **舊自訂 slug**（例如 `niuniu`、`zhuwo_zhonghe`）→ 不能自動改成寄賣編號，要總部人工確認後再對應。
4. **POS 帳號** → 永遠掛寄賣店。找不到對應核銷 slug，不代表店員帳號要重做，只代表核銷還沒接上。
5. **無法自動判斷** → 只有總部可以確認。店員不能自己合併。

---

## 判定方式（先寫再統計）

### 可自動確認是同一家

只有這一條：

> 核銷 slug ＝ 把寄賣編號轉成小寫、把 `-` 換成 `_`  
> 例：`MER-0018` → `mer_0018`

這條通過，才算同一家店。

### 可自動確認是不同家

- 店名像同一招牌、不同分店，例如「豬窩中和店」與「豬窩板橋店」
- 兩筆寄賣店店名相同，但城市或地址不同

這類**不要合併**。

### 需要總部人工確認

- 店名相同或很像，但 slug 對不上編號
- 一筆核銷店可能對到兩筆寄賣店
- 一筆寄賣店可能對到兩筆核銷店
- 兩個會員共用同一支電話

人工確認時只問：

1. 是不是同一間實體店（同一地址）？
2. 還是分店、改名、或舊資料重複？

不確定就維持兩筆，不要開通到錯誤編號。

### 完全無法對應

- 只有核銷、沒有任何像的寄賣店
- 只有寄賣、沒有任何像的核銷店
- 交易或折價券寫著一個不存在的店家編號
- 會員有換罐紀錄，但沒有店、或店編號找不到
- 同一個 LINE 綁在兩個會員編號上（這是資料錯誤，可自動標出，但仍由總部決定怎麼處理）

---

## 明確不做的事

- 不靠店名自動合併
- 不新增、不修正、不刪除正式資料
- 不觸發 LINE、付款或店家同步
- 不在報告裡顯示會員姓名、電話、LINE
- 現在不做「換罐計畫內新增／開通店家」

下一圈才是：先用唯一編號找店，找到就開合作功能，確認不存在才新增。
