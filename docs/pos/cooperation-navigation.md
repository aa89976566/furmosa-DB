# POS 合作入口與導覽調整

本次只修改 POS 操作介面及新增唯讀查詢，不改任何既有店家庫存、銷售、點數、券或結算金額。

## 已實作

- 主導覽統一為首頁、庫存、紀錄、對帳，手機與桌機共用同一份路由定義。
- 首頁提供換罐計畫、寄賣銷售、活動／團購三個入口，下方沿用原有待辦。
- 換罐與寄賣沿用 `/pos/refill`、`/pos/sell`。移除主導覽項目不刪除頁面或流程。
- 右上角通知鈴鐺可展開最近五筆通知，提供載入、空清單、失敗狀態及全部通知入口。資料由 POS session 決定店家，前端不傳 merchantId。開啟通知不寫入任何已讀或完成狀態，也不以待辦數冒充未讀數。
- 共用右上角查詢可搜尋紀錄，查詢字串傳入紀錄頁既有篩選器。庫存原有商品／SKU 搜尋、換罐序號查詢、寄賣商品搜尋及對帳日期／明細篩選保留。
- 新增 `/pos/group-buy`，唯讀顯示登入店家的既有 `MerchantWholesalePrice`，支援商品名稱／SKU 搜尋。不創造活動價格、不把它當活動訂單、不借用寄賣結帳。

## 資料保護

未修改 schema.prisma、migration、seed、庫存異動、分潤計算、正式環境變數或權限驗證。未執行 migration、db push、seed、正式資料修改、正式部署。歷史空規格庫存的相容處理沿用原實作。

這一版不會自動把所有肉乾改為 20% 或凍乾改為 30%，也不會覆蓋店家既有商品規則。既有結算流程尚無正式快照持久化，本次不聲稱解決該問題。

## 需要下一階段確認的設定與資料設計

下列是待審查計畫，未修改 schema 或執行 SQL：

1. 合作方案：以店家＋模式建立可啟用／停用的設定，具生效日期。未設定的舊店家保留既有操作，不從商品名稱或舊庫存推定合作模式。設定啟用只影響新單。
2. 分潤版本：在新設定中新增分類預設（肉乾 20%、凍乾 30%）與店家／商品例外規則；優先序為明確核准的單筆例外、店家商品規則、店家分類規則。交易項目保存規則版本、計價基礎、比例、抽成與匠寵應收快照。舊單不重算。需先確認商品分類對應、折扣與退貨基礎。
3. 活動訂單：活動、期間、店家資格、商品規格、優惠單價；明確區分買斷與寄賣。買斷單不得再算寄賣抽成。新單保存活動與單價快照；舊補貨單不得自動轉成活動單。
4. 點數與券：保留用戶點數及現有官方 LINE 查詢。店家 POS 顯示核銷與補貼；不得再因同一張已核銷券產生另一張店家進貨折抵券。補貼入帳須依原券唯一識別去重；保留既有特殊店家券面額。
5. 結算表頭與明細：新增結算期間、店家、模式、幣別、金額與狀態；明細引用原交易唯一識別。以唯一鍵防止同一筆交易重複結算。更正採沖銷／調整紀錄，不覆寫已結算快照。金額儲存方式與四捨五入規則另列測試，不改歷史 Float 欄位。
6. 庫存：保留現有庫存與異動表；新交易加來源關聯，不拆分或搬移舊 stock rows。若將來需區分貨權，先確認盤點及期初方案，不以模式切換觸發異動。

影響：僅新增設定／新單快照及結算關聯；不得刪表、刪欄位或自動回填歷史資料。需先於隔離測試資料庫驗證，再提交正式 migration 審查。

回復：以功能開關停用新模式與新結算寫入，回到既有路由。已產生的新交易與結算紀錄保留供稽核，不以刪除資料作為 rollback。若正式 migration 尚未執行，可直接撤回 migration 檔。
