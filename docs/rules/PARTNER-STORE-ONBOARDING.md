# 合作店家建立規則

## 單一資料來源

- 一個實體門市只建立一筆 `Merchant`。
- 店家名稱是主體；聯絡人姓名只代表接洽人，不得拿來當店名。
- 寄賣、販售、換罐計畫是同一店家的可複選合作方式，不建立三套店家資料。
- 同一店家新增合作方式時，合併既有 `types`，不得覆蓋其他合作方式或店家標籤。

## 建立流程

1. 先用店名、店家編號或電話搜尋。
2. 找到既有店家時，選用該店並開通合作方式。
3. 找不到時才可建立新店家。
4. 新增前，伺服器必須再次比對正規化店名與電話，不能只依賴畫面搜尋。
5. 建立或開通完成後，再設定該店 POS 帳號。

## POS 權限

- HQ 與 POS 使用不同登入狀態；HQ 登入不得等同 POS 登入。
- POS 的 `merchantId` 一律由登入狀態取得，不接受前端傳入的店家編號作為查詢範圍。
- 第一階段一個實體門市只保留一個使用中的 POS 帳號。
- 密碼只存雜湊，不寫入紀錄、不回傳明文。
- 建立帳號前必須再次確認 HQ 登入狀態。

## 合作方式

| 值 | 畫面名稱 | 意義 |
| --- | --- | --- |
| `consignment` | 寄賣 | 商品放店內，售出後對帳 |
| `wholesale` | 販售 | 店家買斷進貨 |
| `jar_exchange` | 換罐 | 提供一罐換一罐服務 |

合作方式不得預先勾選，必須由操作者明確選擇。

## 暫不包含

- 不在此流程直接設定每項商品、價格或庫存。
- 不在此流程建立第二套會員或店家主檔。
- 未有資料表支援前，不宣稱密碼可強制首次登入更換。
