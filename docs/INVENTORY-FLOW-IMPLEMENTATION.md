# HQ 庫存流通改版工作計畫

確認日期：2026-10-25。使用者要求沿用現有「新增進貨」，簡單操作並接通 HQ、出貨及 POS；不建立平行庫存。

## 已確認原則

- 商品／規格 ID 為共用身分；SKU 為外部映射，禁止靠名稱猜測合併。
- 新增商品不增加數量；未到貨進貨單不增加數量；確認實收才入庫。
- 出貨扣 HQ 出貨倉；店家收貨加店家庫存；POS 售出只扣店家，禁止重扣 HQ。
- 平常只看目前庫存；盤點才填現場剩餘總量。空白不動、0 表示歸零。
- 進貨填本次新增量，不得當成盤點總量。
- 保留原成本、單據、出貨及異動歷史。未知成本不當成 0。
- 供應商、真實進貨日期可標記待補，系統登記／確認時間獨立保留，不假填。
- 散裝 g、雞霸片、鴨翅與鵪鶉隻、成品包：必須確認主檔與銷售規格，不能任意換算。
- 新品應可從進貨流程建立後返回原單；組合品需確認組裝模式再扣組成品。

## 現況限制（已讀取程式核對）

- 首頁「新增進貨」連到 purchase-orders/new，但 purchases/new 又是另一直接入庫入口。
- purchase_orders 與 purchase_receipts 是一對一；收貨用原訂購量全量入庫。
- quantityGrams、averageCostPerGram 及入庫成本服務以 g 為主。
- 入庫日期、品項金額為必填；目前不能宣稱支援待補日期／成本。
- 採購單收貨已有唯一關聯與冪等；直接入庫缺少表單層提交識別碼。
- 出貨已有資料庫扣庫觸發器，不得另加服務重複扣庫。
- 已開啟頁面不會因其他人操作立即推播；需要背景刷新且盤點中禁止覆寫基準。

## WP1 驗收

1. 所有「新增進貨」進入同一選擇頁；尚未到貨不會加庫存；已有進貨單者不重新建立直接入庫。
2. 正常列表無逐列更新按鈕；非盤點模式無數量輸入欄。
3. 空白與未變更不送出，負數／小數被擋；篩選不丟盤點草稿。
4. 儲存沿用伺服器權限、版本檢查及冪等，且不調整成本。
5. 未授權者無盤點入口；單位修正僅管理員、預設收合。
6. 入庫成功即使顯示更新失敗仍導向已建立單據，不回到可重送表單誤報失敗。
7. 正式資料不作示範變更。未通過部署及 smoke 不宣稱已上線。
