# HQ 散裝克數換算 Shopify 包數

## 本次範圍

`lib/inventory/sellable-packs.ts` 是純計算／檢查核心。
`load-hq-pack-preview.ts` 已新增 HQ 唯讀資料載入函式：由呼叫端傳入 DB 與明確倉庫代碼，
在同一 Repeatable Read 交易讀取有效規格、既有組合配方、散裝來源與該倉庫帳面量。
尚未接管理介面、正式執行、占用帳或 Shopify 寫入。
不可宣稱已啟用自動同步。未變更 schema、正式庫存、排程或 webhook。

## 已確認商業規則

- HQ 克數為唯一庫存來源；未分裝亦可販售。
- 可用克數 = 帳面克數 − 尚未出貨且尚未扣帳的占用克數。
- 鮭魚皮 50g：100g 無占用時可售 2 包；占用 50g 時可售 1 包。
- 家有三寶 45g：依已核准配方三種原料各耗用 15g，取最少可組包數。
- 出貨時既有扣料帳減少帳面克數，該部分占用也須移除；不得重複扣減。
- 取消未出貨數量釋放占用；已出貨取消不能直接當成退貨回庫。

## 計算保護

缺少原料、單位未核實、占用讀取不完整、配方錯誤、重複變體綁定均回傳阻擋原因，沒有可發布數量。
負庫存回傳 0。多規格或多組合共用原料時，回傳 `SHARED_POOL_REQUIRES_ALLOCATION`，避免每款各自發布全部原料容量。
`snapshotComplete` 必須由呼叫端確認同一倉庫範圍、同一資料快照，且已完整計入所有通路未扣帳需求後才能設為 true。

## 尚待整合與驗收

1. 唯讀載入函式已實作；仍須在隔離資料庫驗證及接管理介面。未綁 Shopify 的 HQ 克重規格也參與共料檢查；配方總重與規格不一致時阻擋。
2. 依訂單、部分出貨及實際扣帳紀錄計算未扣帳需求，保留事件去重與取消釋放。
3. 為共用原料建立明確可售量分配策略；占用建立必須有跨通路原子性保護。
4. 串接 Shopify 單一指定地點的 inventory item，使用比較後寫入，防止覆蓋並行下單扣量。
5. 補貨、盤點、下單、取消與出貨觸發受控同步；重送不重複占用／扣料。
6. 隔離環境驗證兩款完整流程與並行最後一包，才進入正式發布。
