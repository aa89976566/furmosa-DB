## 0. 設計憲法

1. **一天三件事：** 今天／叫貨／紀錄。  
2. **一屏一主動作。** 主 CTA ≥ 44px。  
3. **店員語言。** 禁止 HQ／Appointment／Refill 等詞。  
4. **點擊預算 ≤ 3**（從「今天」到完成常見任務）。  
5. **完成 → 下一位或回今天。**  
6. **手機優先；平板同結構加寬。**

### 0.1 店員的一天

```text
09:00 登入
  → 「今天」固定四類待辦（有數量才顯示）
  → 服務客人／收空罐交商品
  → 缺貨就叫貨
  → 下班前看「今天的紀錄」
```

### 0.2 底部架構（定案）

```text
今天
├── 下一位客人
├── 待換罐
├── 缺貨提醒
└── 補貨進度
叫貨
├── 我要自己選
├── 請幫我配
└── 申請進度
紀錄
└── 今天完成的美容、換罐與叫貨
```

```text
┌─────────────────────────────┐
│  （內容區）                   │
├─────────┬─────────┬─────────┤
│  今天   │  叫貨   │  紀錄   │
└─────────┴─────────┴─────────┘
```

登出＝「今天」右上角小字。

## 2. Merchant Dashboard（今天）

### 2.1 固定排序（無 urgency score）

```text
豬窩中和店                         登出
─────────────────────────────────
今天

1. 下一位客人     豆豆 · 13:30     →
2. 待換罐         3               →
3. 缺貨提醒       雞肉剩 2         →
4. 補貨進度       1 張處理中       →
```

- **只顯示數量 > 0**（或明確有下一筆客人）的列。  
- **不做**動態「最緊急加重」演算法。

| 欄位 | 內容 |
|------|------|
| **Goal** | 3 秒看完待辦；一點進任務 |
| **Primary CTA** | 列表中**第一個有內容的列**（固定順序的自然結果，不是 score） |
| **Secondary CTA** | 其他列；底 Tab |
| **Empty State** | 「今天都處理好了。」＋次要「需要補貨嗎？」→ 叫貨 |
| **Error State** | 「資料暫時載不進來，下拉再試」 |
| **Mobile** | 大列可點，min-height ~72px |
| **Tablet** | 同序，可加寬 |
| **Required Data** | 下一客摘要、待換罐數、可靠低庫存、補貨申請進行中筆數 |
| **Clicks** | **1** 進任務 |

### 2.2 點擊規則

- **待換罐：** 進入「現在最適合處理的一筆」（§4.1）；無法判斷則進精簡佇列。  
- **缺貨：** 進叫貨，預填建議量（§8）；未設定則 **1**。  
- **補貨進度：** 該申請唯讀詳情。  
- **下一位客人：** 進該客任務卡（§3）。

**不做：** Menu、報表、設定 Tab。

## 3. Today's Grooming（客人）— 美容狀態最小集

### 3.1 第一版候選狀態（可實作方向）

- 待到店  
- 已到店  
- 美容完成  
- 未到店  
- 已取消  

### 3.2 兩種方案（Phase 4 前訪談決定）— **待驗證 V-01**

**方案 A（建議預設，較少點擊）**

```text
已到店 → 美容完成
```

**方案 B（多一步「服務中」）**

```text
已到店 → 服務中 → 美容完成
```

> 「開始美容」**不是**第一版必要操作；文件可保留構想，標 **待驗證**，未訪談前不強制。

### 3.3 單筆任務卡（方案 A 示意）

```text
13:30  豆豆 · 貴賓
主人 王小明
洗澡＋剪毛
狀態：已到店

[ 美容完成 ]          ← 主 CTA（方案 A）
[ 接著換罐 ]          ← 僅當今日有已付款待交付換罐
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 標完成或接到收罐 |
| **Primary CTA** | 美容完成／接著換罐（依情境） |
| **Secondary CTA** | 標未到店（謹慎、需確認） |
| **Empty / Error** | 「找不到這筆」→ 回今天 |
| **Clicks** | ≤ **2**（待驗證） |
| **Required Data** | 時間、寵物、服務、顧客、換罐付款／交付狀態 |

## 4. Pending Refill Delivery（待換罐）

### 4.1 選哪一筆（不可盲目「第一筆」）

優先順序（僅當狀態**可靠**時）：

1. 已到店  
2. 服務中（若採用方案 B）  
3. 預約時間距離現在最近  

**若無法可靠判斷是否已到店：** 顯示精簡佇列讓店員選，**不要假裝系統知道誰在現場**。

```text
待換罐  3

13:30 豆豆 · 已付款 · 要 1 罐
14:00 球球 · 已付款 · 要 2 罐   ← 店員點選
17:00 咪咪 · 已付款 · 要 1 罐
```

### 4.2 單罐

```text
13:30  豆豆
已付款 · 需要 1 個空罐

輸入瓶底序號
┌─────────────────────┐
│                     │
└─────────────────────┘

[ 確認收到並交付 ]   ← 驗證成功後可點；點後進短確認
```

### 4.3 多罐（requiredReturnQty > 1）

```text
需要 2 個空罐

空罐 1
[ A1234567 ]     已確認 ✓

空罐 2
[ ________ ]     等待輸入

[ 確認收到並交付 ]   ← 全部驗證成功前禁用
```

規則：

- 逐個輸入、逐個驗證；**禁止**逗號、空格串、textarea。  
- 每個序號：不得重複、屬本次顧客、仍可換、未被其他交換占用。  
- 主按鈕僅在**全部**驗證成功後解鎖。

### 4.4 短確認（同一任務，非第二技術頁）

```text
已收到 2 個空罐，並把商品交給豆豆的主人？

[ 確認完成 ]     ← 最終主 CTA
[ 返回修改 ]
```

語意＝店員已同時完成：

1. 實際收到指定數量空罐  
2. 實際把商品交給顧客  

### 4.5 成功

```text
已交付 ✓

[ 下一位 ]      ← 有下一筆最適合處理者
[ 回今天 ]      ← 若無下一筆則此為主 CTA
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 收罐＋交付一次做完 |
| **Primary CTA** | 確認完成（確認層）／下一位或回今天（成功層） |
| **Secondary CTA** | 補 30 元連結／保留下次領（忘帶罐，僅兩路） |
| **Error State** | 日常語言（找不到序號／不屬於本客／已換過／未付款／數量未齊） |
| **Mobile** | 大數字鍵盤；主鈕近拇指 |
| **Clicks** | 從今天起目標 ≤ **3**（含確認完成） |
| **Required Data** | 顧客／寵物、requiredReturnQty、付款、本店預留、可驗證序號 |

店員**不**輸新罐、**不**加點、**不**標記付款。

## 5. One-click Restock（叫貨）

### 5.1 入口

```text
[ 我要自己選 ]
[ 請幫我配 ]
```

另可從「申請進度」看唯讀狀態。

| **Clicks** | 選模式 **1** |

### 5.2 我要自己選 / 請幫我配

同既有 Phase 2 能力映射（見文末 §映射）：數量加減／備註／送出；狀態用語：公司確認中／已確認／備貨中／需要調整／預計到貨。

店員不可核准、改 HQ 數量、開出貨單。

| **Clicks** | 送出 **1**；從入口 ≤ **3** |

## 6. Inventory Warning（缺貨提醒）

- **僅在門市庫存可靠時顯示**（否則 Dashboard 不出現此列）。  
- **不做**預測補貨演算法。  
- 建議量：`MerchantSettings` 固定補貨量，或補到目標量；**未設定 → 預設 1**，店員自行加。

```text
⚠ 需要補貨
雞肉凍乾  剩 2   [ 加入叫貨 ]
[ 一次叫這些 ]
```

| **Clicks** | Dashboard → 一次叫這些 → 送出：**2～3** |

第一版不做盤點／調帳／成本報表。

## 8. Customer Detail（任務型）

**只顯示：**

- 顧客姓名、電話  
- 寵物姓名、品種  
- 今日服務  
- 今日換罐狀態  
- 必要照護備註（服務當下需要的）  

**不要放：** 終身消費、跨店資料、完整點數帳本、財務、行銷標籤、他店內部評分。

店家只看**本店／本次服務必要**資料。

| **Primary CTA** | 去收空罐／進入今日服務（依狀態） | **Clicks** | **1** |

## 9. 點擊預算總表

| 任務 | 目標點擊 | 路徑 |
|------|----------|------|
| 登入→今天 | 1 | 登入 |
| 收罐並交付（含短確認） | ≤ 3 | 待換罐 → 輸序號 → 確認完成 |
| 自己選叫貨 | ≤ 3 | 叫貨 → 自己選 → 送出 |
| 請幫我配 | ≤ 2 | 叫貨 → 請幫我配 → 送出 |
| 缺貨轉叫貨 | ≤ 3 | 缺貨 → 一次叫這些 → 送出 |

超過 4 次 → 重畫，不加頁。
