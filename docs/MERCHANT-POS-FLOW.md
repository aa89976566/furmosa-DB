# Furmosa Merchant POS Flow — Phase 2.5

> **地位：** Merchant Experience Design（任務流，不是 Schema）  
> **版本：** v1.0-draft  
> **日期：** 2026-07-22  
> **原則：** Task-first，不是 Entity-first。成功標準 = 店員用最少決策完成今天的工作。  
> **禁止：** 本文件不討論 Prisma、Event、Asset Transfer、Domain 名詞給店員看。

---

## 0. 設計憲法（給所有畫面）

1. **一天三件事：** 今天／叫貨／歷史。第一版底部只有這三個。無 Sidebar、無 Reports Menu。  
2. **一屏一主動作。** 主 CTA ≥ 44px，滿寬優先。  
3. **用語是店員語言：** 已付款、輸入瓶底序號、確認收到、雞肉剩 2。不要 HQ／Appointment／Refill。  
4. **點擊預算：** 常見任務目標 ≤ 3 次點擊（從 Dashboard 起算到完成）。  
5. **完成即回「下一位」或「今天」。** 不要把人丟進列表迷宮。  
6. **手機優先；平板＝同結構加寬。** 不做桌面後台感。

### 0.1 店員的一天（北極星旅程）

```text
09:00 登入
  → 看「今天」四件事（客人／待換罐／缺貨／補貨）
  → 做美容
  → 收空罐（輸入序號 → 確認收到）
  → 交商品
  → 缺貨就叫貨
  → 下班前看「歷史」一眼
```

### 0.2 全域導航（第一版）

```text
┌─────────────────────────────┐
│  （內容區）                   │
├─────────┬─────────┬─────────┤
│  今天   │  叫貨   │  歷史   │
└─────────┴─────────┴─────────┘
```

登出藏在「今天」右上角小字，不是主 CTA。

## 1. Merchant Login

| 欄位 | 內容 |
|------|------|
| **Goal** | 用帳號密碼進入本店「今天」 |
| **Primary CTA** | 登入 |
| **Secondary CTA** | 無（問題請聯繫總部 — 靜態文字） |
| **Empty State** | 空白表單，帳號／密碼欄 |
| **Error State** | 「帳號或密碼不正確」／「此帳號已停用，請聯繫 Furmosa 總部」；不洩漏哪一邊錯 |
| **Mobile** | 單欄置中，大輸入框，主按鈕滿寬 |
| **Tablet** | 同結構，最大寬約 420px 置中 |
| **Required Data** | username、password → session（本店） |
| **Clicks** | 填寫後 **1** 次（登入）→ 到達「今天」 |

**不需要的步驟：** 選店、選角色、看教學輪播。

## 2. Merchant Dashboard（＝「今天」）

> 這不是報表。這是**今天要處理的工作佇列摘要**。

### 2.1 畫面結構

```text
豬窩中和店                         登出
─────────────────────────────────
今天

🐶  8 位客人          →
🫙  3 個待換罐        →
⚠   雞肉剩 2          →
📦  1 張補貨待確認     →
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 3 秒內知道今天忙什麼；一點進入對應任務 |
| **Primary CTA** | 最緊急的那一列（通常「待換罐」或「下一位客人」）— 視覺上可把第一個有數字的列加重 |
| **Secondary CTA** | 其他摘要列；底部「叫貨／歷史」 |
| **Empty State** | 「今天沒有預約。需要補貨嗎？」＋一個「去叫貨」 |
| **Error State** | 「資料暫時載不進來，下拉再試」 |
| **Mobile** | 四張大列（min-height ~72px），整列可點 |
| **Tablet** | 同上，可 2×2 網格，但保持同一資訊密度 |
| **Required Data** | 今日預約數、待交付換罐數、低於閾值的 SKU、進行中補貨申請數 |
| **Clicks** | 進入任一任務 **1** 次 |

### 2.2 點擊規則

- 點「3 個待換罐」→ 直接進**待換罐佇列第一筆**（不是先到列表再點）。可選：若要掃一眼列表，佇列頁頂部仍顯示「還有 2 位」。  
- 點「雞肉剩 2」→ 叫貨頁，該品項數量已預填建議值（例如 1 箱或 +10）。  
- 點「補貨待確認」→ 該申請詳情（唯讀進度）。

**明確不做在 Dashboard：** Menu、報表、設定、多頁 Tab。

## 3. Today's Grooming（今天的狗）

### 3.1 列表（僅在需要掃一眼時出現）

從 Dashboard「8 位客人」進入時：預設可**直接開下一筆未完成**；列表是次要。

```text
今天的客人                    還有 5 位

13:30  豆豆 · 貴賓              [開始]
15:00  咪咪 · 柯基              等待中
…
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 找到現在這隻／下一位，開始服務 |
| **Primary CTA** | 開始／繼續（當前時段） |
| **Secondary CTA** | 打電話給客人（系統只顯示號碼，不強制） |
| **Empty State** | 「今天沒有客人」 |
| **Error State** | 「找不到這筆預約」→ 回今天 |
| **Mobile** | 時間＋寵物名最大；狀態一顆字 |
| **Tablet** | 左列表右詳情（可選）；手機保持單欄 |
| **Required Data** | 時間、寵物名、品種／服務名、顧客名、是否含換罐 |
| **Clicks** | Dashboard → 開始：**1～2** |

### 3.2 單筆進行中

```text
13:30  豆豆
主人 王小明
洗澡＋剪毛

狀態：進行中

[ 美容完成 ]
[ 接著換罐 ]   ← 僅當本筆有已付款換罐時出現
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 標完成，或無縫接到收罐 |
| **Primary CTA** | 美容完成（若無換罐）／接著換罐（若有） |
| **Secondary CTA** | 稍後再做換罐（回今天） |
| **Empty／Error** | 不適用；錯誤→「無法更新，再試一次」 |
| **Clicks** | 完成美容 **1**；有換罐則進收罐流 **+0～1**（同一任務鏈） |

## 4. Pending Refill Delivery（待換罐）

> 店員心智模型：**收空罐 → 交商品**。不是 RefillOrder。

### 4.1 佇列（盡量跳過）

若從 Dashboard 進來且只有 1 筆：直接進 4.2。  
多筆時：

```text
待換罐  3

13:30 豆豆 · 已付款 · 要 1 個空罐
15:00 球球 · 已付款 · 要 2 個空罐
```

| **Clicks** | 選一筆 **1**（若已直達則 0） |

### 4.2 收罐畫面（核心）

```text
13:30  豆豆
已付款 · 需要 1 個空罐

輸入瓶底序號
┌─────────────────────┐
│                     │
└─────────────────────┘

[ 確認收到並交付 ]     ← 唯一主 CTA

忘帶空罐？
  補 30 元連結    保留下次領
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 驗舊罐並完成交付；店員不用輸新罐、不加點、不碰金流 |
| **Primary CTA** | 確認收到並交付（首罐／已補差：確認交付商品） |
| **Secondary CTA** | 補 30 元連結／保留下次領（僅兩個，禁止第三條路） |
| **Empty State** | 序號欄空白，按鈕可點但驗證失敗會擋 |
| **Error State（日常語言）** | 「找不到這個序號，請再確認瓶底 8 碼。」「這個罐子不屬於本次顧客。」「這個序號已經換過。」「這筆還沒付款，暫時無法交付。」「需要 2 個空罐，目前只確認 1 個。」 |
| **Mobile** | 序號框超大、數字鍵盤；主按鈕固定近拇指區 |
| **Tablet** | 同結構，可並排顯示寵物名與付款狀態 |
| **Required Data** | 顧客／寵物、應付空罐數、付款狀態、本店預留、可驗證序號 |
| **Clicks** | 輸入後確認：**1** 次主 CTA。從 Dashboard 起算目標 **≤ 3** |

### 4.3 成功

```text
已交付 ✓

[ 下一位待換罐 ]   或   [ 回今天 ]
```

| **Clicks** | **1** |

**成功後系統在背景：** 引導顧客 LINE 登新罐累點（店員無感）。

## 5. One-click Restock（叫貨）

底部 Tab「叫貨」或 Dashboard 缺貨列進入。

### 5.1 入口

```text
補貨

[ 我要自己選 ]
[ 請幫我配 ]
```

| **Primary CTA** | 二選一其一 | **Clicks** | **1** |

### 5.2 我要自己選

```text
雞肉凍乾     門市 2    [−] 10 [+]
牛肉⋯                  [−]  0 [+]
備註 ________
[ 送出申請 ]
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 選數量送出，等待公司 |
| **Primary CTA** | 送出申請 |
| **Secondary CTA** | 返回 |
| **Empty State** | 「目前沒有可叫的商品，請聯繫 Furmosa」 |
| **Error State** | 「請至少選一個數量大於 0 的商品」 |
| **Required Data** | 換罐可叫貨商品、門市庫存（有才顯示）、數量 |
| **Clicks** | 調數量（不計）＋送出 **1**；從入口起 **≤ 3** |

### 5.3 請幫我配

```text
告訴我們你需要什麼
┌─────────────────────┐
│ 常用款快沒了，幫我配  │
└─────────────────────┘
[ 送出申請 ]
```

| **Clicks** | **1** |

### 5.4 申請進度（唯讀）

狀態用語：公司確認中／已確認／備貨中／需要調整／預計到貨日期。

店員**不能**：核准、改數量、開出貨單。

## 6. Inventory Warning（缺貨）

不是獨立「庫存模組首頁」，而是 **Dashboard 上的一列／點進去的短任務**。

```text
⚠ 需要補貨

雞肉凍乾    剩 2    [ 加入叫貨 ]
牛肉零食    剩 0    [ 加入叫貨 ]

[ 一次叫這些 ]
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 把缺貨轉成叫貨，不要先學庫存盤點 |
| **Primary CTA** | 一次叫這些／加入叫貨 |
| **Secondary CTA** | 稍後 |
| **Empty State** | 「庫存看起來夠用」→ 回今天 |
| **Error State** | 「無法加入，請稍後再試」 |
| **Required Data** | SKU 名稱、門市量、建議補量 |
| **Clicks** | Dashboard → 一次叫這些 → 送出：**2～3** |

**第一版不做：** 盤點、調帳、成本、報表。

## 7. Today's History（歷史）

底部「歷史」＝**今天做完什麼**（不是會計總帳）。

```text
今天做完的

15:40  豆豆換罐已交付
15:10  咪咪美容完成
14:02  送出補貨申請
…
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 下班前確認沒漏；出錯可點進去看（唯讀） |
| **Primary CTA** | 無（瀏覽）；列可點看詳情 |
| **Secondary CTA** | 回今天 |
| **Empty State** | 「今天還沒有完成的紀錄」 |
| **Error State** | 「載入失敗」 |
| **Required Data** | 今日已完成美容／交付／叫貨時間線 |
| **Clicks** | 掃一眼 **0**；看詳情 **1** |

**不做：** 跨月報表、篩選器叢林、匯出。

## 8. Customer Detail（客人）

> 從「今天的客人」點名字進入。不是 CRM 後台。

```text
王小明
豆豆 · 貴賓 · 4 歲

今天
13:30 洗澡＋剪毛
換罐：已付款 · 待收空罐

[ 去收空罐 ]     ← 若待換罐
[ 打電話 ]
```

| 欄位 | 內容 |
|------|------|
| **Goal** | 服務當下需要的最小資訊＋跳回任務 |
| **Primary CTA** | 去收空罐／開始美容（依狀態） |
| **Secondary CTA** | 打電話 |
| **Empty State** | 無今日任務：「沒有今天的安排」 |
| **Error State** | 「找不到這位客人」 |
| **Required Data** | 名、寵物、今日預約、換罐付款／交付狀態、電話 |
| **Clicks** | 進任務 **1** |

**第一版不放：** 終身消費、點數明細表、跨店評價編輯（可後補）。

## 9. 點擊預算總表（成功標準）

| 任務 | 目標點擊（從「今天」起） | 路徑 |
|------|-------------------------|------|
| 登入到看到今天 | 1 | 登入 |
| 完成一筆收空罐交付 | ≤ 3 | 待換罐 →（直達）→ 確認收到 |
| 送出自己選叫貨 | ≤ 3 | 叫貨 → 自己選 → 送出 |
| 請幫我配 | ≤ 2 | 叫貨 → 請幫我配 → 送出 |
| 缺貨轉叫貨 | ≤ 3 | 缺貨列 → 一次叫這些 → 送出 |
| 美容完成 | ≤ 2 | 客人 → 美容完成 |

若任何常見任務設計超過 **4** 次點擊：重畫，不要加頁。

## 10. 對照：工程師流 vs 店員流（刻意刪掉的步驟）

| 不要做的（Entity） | 改成（Task） |
|--------------------|--------------|
| Booking → Appointment → Refill → Order → Verify → Submit | 待換罐 → 輸入序號 → 確認收到 |
| 開 Inventory 模組 → 選 SKU → 建單 | 雞肉剩 2 → 一次叫這些 |
| 側欄七個選單 | 今天／叫貨／歷史 |

## 11. HQ 一日流（附錄，非店員 POS）

```text
登入 HQ
→ 誰在等補貨核准
→ 調數量＋到貨日 → 核准
→ 看出貨隊列今天寄什麼
→ 完成
```

HQ 可有 Sidebar；**店員 POS 不要抄 HQ 資訊架構**。

## 12. Customer LINE 一日流（附錄）

```text
預約 → 付款 → 提醒 → 到店洗澡 → 帶空罐
→（店家收罐）→ LINE 輸入新序號 → 看點數
```

店員端**不負責**幫客人輸新序號。
