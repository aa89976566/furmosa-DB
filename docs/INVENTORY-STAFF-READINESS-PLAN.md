## 工作順序

1. 進貨表單：送出鎖定、錯誤保留欄位與提交識別；檔案需重新選取時明示。完成前不宣稱防重送體驗完整。
2. 日期與廠商待補：廠商既有 nullable；日期需以下 schema 計畫核准後實作。不得用今天取代未知日期。
3. 未知成本：獨立設計待核成本流程，禁止以 0 寫入現有移動平均。未完成前維持既有已知成本限制。
4. 核對 Sheet 剩餘品項及單位；列出待人員確認事項，不推測包／片／隻的克數。
5. 隔離環境驗收進貨、實收、出貨、取消、店家收貨、POS 銷售與退款。核對既有資料庫 trigger，不另加重複扣庫。
6. 手機與桌機驗收、角色權限、操作說明，最後受控發布。

## 待核准的日期資料結構變更

目的：允許實際進貨日期未知；登記時間繼續由 createdAt／postedAt 留存。
- PurchaseReceipt.receiptDate 改 nullable；僅 DROP NOT NULL，不改舊值、不回填。
- 新增獨立的資料補正稽核紀錄（原值、新值、操作人、補正時間），具體模型另在實作前列出。
- 補資料服務只更新 metadata 和稽核，不呼叫入庫／成本服務，不建立數量流水。
- 清單與詳情顯示「日期待補」，排序以已知日期或登記時間處理；不將登記時間顯示成真實到貨日。
- 供應商補填仍須處理 vendor + supplierDocumentNumber 唯一衝突，失敗時原子回復。
- 分批與直接入庫日期分開核對；分批當下確認收貨時間不能冒充未知歷史採購日期。

影響：Prisma 型別、日期格式函式、入庫編號產生、查詢排序、清單、詳情、補資料表單及測試。
回復：保留既有值；新 nullable 資料存在後不能直接回退舊程式或恢復 NOT NULL。停止相關寫入、以相容版本修正向前，不假填日期、不刪資料。
驗收：空日期成功、舊日期不變、待補可搜尋、補正不增加庫存、權限防護、稽核保存、唯一衝突完整回復。
